!!! info "API Reference Update — Security & Compliance Integration"
    **Feature Update**: Integrated `cube3` Security Inspector API for real-time destination address screening.  
    **New Parameter**: `screeningFlag` (boolean) added to `Send-Many-Transaction-Object-Request`.  
    **Behavior**: Automatically screens destination addresses for cyber, fraud, and compliance threats. If any destination address has a combined **Risk Score > 80**, the entire transaction request is aborted and returns **HTTP 400 Bad Request** containing threat details for the **first blocked address**.

---

## Description

This API is a request to execute a single or multiple transactions from a v1 withdrawal wallet to the specified destination address(es). EVM chains support transfers to a single address, while UTXO chains support transfers to one or more addresses. You can transfer funds in either native coin or token in a single request.

For opt-in asset chains like **XRP** and **Stellar (XLM)**, use `wallet.transactionType = "enableToken"` to establish a one-time trust line before sending or receiving token assets.

With the integration of **Cube3 Security Inspector**, destination addresses can be evaluated for security threats (such as sanctioned entities, drainer contracts, and malicious actors) prior to broadcasting transactions on-chain.

---

## Explicit Technical Assumptions & Specifications

1. **HTTP Status Code Standardization**: As mandated by the specification, all threat screening rejections (Risk Score > 80) are handled via **HTTP 400 Bad Request**.
2. **First Blocked Address Atomic Rejection**: Even if a single address in a multi-recipient batch fails screening, all transactions in the request are aborted atomically, and the risk details for the **first blocked address** are returned.
3. **Unchanged Response for Disabled Screening**: When `screeningFlag` is `false` or omitted, transactions are not screened, and there is **no change in the response structure** (i.e., `screeningResult` and `screeningID` are omitted from the success response payload).
4. **Error Object Schema**: Screening rejection errors use an `error` array inside `data` (matching standard 400 error arrays) with `screeningResult: "blocked"`, `screeningID`, `riskScore` as a string, `msg`, and `param` mapped to `recipientsData.recipients[N].address`.

---

## Parameter Guidelines & Validation Rules

Accepted parameter values:

1. The `transactions.recipientsData.recipients[].address` parameter must have a valid address length (> 0). It will not accept any null value or empty `String` value.
2. The data type of `transactions.recipientsData.recipients[].amount` is updated to `String` and must be a positive decimal string. It will not accept empty string, null, or number value.
3. The `transactions.recipientsData.sequenceId` parameter is a required unique tracking identifier (UUID format) generated by the client.
4. **[NEW]** The `screeningFlag` parameter is a `Boolean` (`true` or `false`).
    * When set to `true`, all destination addresses in `transactions.recipientsData.recipients[]` are evaluated via Cube3 Inspector API before broadcast.
    * If any address has a combined **Risk Score > 80**, the entire batch request is aborted and returns **HTTP 400 Bad Request** with risk details for the first blocked address.
    * When set to `false` or omitted, no screening takes place, there is **no change in the response**, and standard payout rules apply.
5. **Asset Enablement (`wallet.transactionType`)**:
    * Set to `"enableToken"` to create a trust line for non-native assets on XRP (`RLUSD`) or Stellar (`USDC`).
    * When `wallet.transactionType` is `"enableToken"`, `transactions.recipientsData.recipients` must be an empty array `[]`.

---

## Optional Parameters

1. **Address Screening (`screeningFlag`)**:
   - `screeningFlag`: Set to `true` to activate automated pre-transaction destination address threat screening. Default is `false`.
2. **Using `feeLevel` and `evmCustomfee`**:
   - The `feeLevel` parameter is applicable for EVM chains (`slow`, `market`, `aggressive`, `custom`). Use only `maxFeePerGas` (Wei) if the `coin` value is `BNB`. Use both parameters for EIP-1559 chains.
   - The `maxPriorityFeePerGas` (Wei) cannot be greater than `maxFeePerGas` (Wei).
   - Use `evmCustomfee` object only when the `feeLevel` parameter is `custom`. Refer to the [Retrieve estimated gas fees and rates](https://docs.lmnl.app/reference/getapproxfees) API reference to get the required fee estimation rates.

```json
{
  "wallet": {
    "coin": "eth",
    "walletId": 14999,
    "allToken": true,
    "tokenOptions": {
      "tokenName": "USDC",
```

### Parameter Reference Table

| Parameter Path | Data Type | Requirement | Description |
| :--- | :--- | :--- | :--- |
| `wallet` | `object` | <span class="param-required">Required</span> | Wallet details object (`coin`, `walletId`, `allToken`, `tokenOptions`). |
| `wallet.coin` | `string` | <span class="param-required">Required</span> | Abbreviated cryptocurrency symbol (e.g., `eth`, `btc`, `sol`, `bnb`, `xrp`, `xlm`). |
| `wallet.walletId` | `integer` | <span class="param-required">Required</span> | Unique identifier of the source withdrawal wallet. |
| `wallet.transactionType` | `string` | <span class="param-optional">Optional</span> <br>*(Default: `"transfer"`)* | Transaction operation type (`"transfer"` or `"enableToken"` for XRP/XLM trust lines). |
| `wallet.allToken` | `boolean` | <span class="param-optional">Optional</span> | Set to `true` when transferring non-native token assets. |
| `wallet.tokenOptions.tokenName` | `string` | <span class="param-optional">Optional</span> | Token symbol name (e.g., `USDC`, `RLUSD`). |
| `wallet.tokenOptions.tokenAddress` | `string` | <span class="param-optional">Optional</span> | Contract address (EVM) or `<AssetCode>.<Issuer>` (XRP) / `<AssetCode>:<Issuer>` (XLM). |
| `transactions.recipientsData.recipients` | `array[object]` | <span class="param-required">Required</span> | Array of recipient objects (`address`, `amount`, `data`). Must be `[]` for `enableToken`. |
| `transactions.recipientsData.recipients[].address` | `string` | <span class="param-required">Required</span> | Target destination wallet address. |
| `transactions.recipientsData.recipients[].amount` | `string` | <span class="param-required">Required</span> | Positive decimal string representing transfer amount. |
| `transactions.recipientsData.sequenceId` | `string` | <span class="param-required">Required</span> | Unique system sequence UUID generated by the client for tracking. |
| **`screeningFlag`** | <span class="param-type">boolean</span> | <span class="param-optional">Optional</span> <br>*(Default: `false`)* | **[NEW]** Controls pre-transaction Cube3 risk screening. Returns HTTP 400 if risk score > 80. |
| `feeLevel` | `string` | <span class="param-optional">Optional</span> | Gas fee tier (`slow`, `market`, `aggressive`, `custom`). |
| `evmCustomfee.maxPriorityFeePerGas` | `string` | <span class="param-optional">Optional</span> | Priority gas fee in Wei. |
| `evmCustomfee.maxFeePerGas` | `string` | <span class="param-optional">Optional</span> | Maximum gas fee in Wei. |

*[withdrawal wallet]: Liminal hot wallet vault configured for outgoing customer payouts.
*[native coin]: Main blockchain protocol currency (e.g., ETH, BTC, SOL, BNB).
*[token]: Secondary token contracts operating on a host blockchain (e.g. ERC-20, SPL tokens).
